# E0T -- Tool-gap closure: execution-pinned tool operation mapping, typed Responses proposals, and durable worker replies (contract revision 21)

Acceptance: Verified against zatiti origin/main 9cd94f7 (REVISION=20). When E0T lands: (1) Every tool in an execution-built zatiti.context/v1 document carries an operation_id and operation_version. Execution chooses them from the pinned tool contract. Sealed decision tools map to zatiti.local_decision.<name>@1. Adapter-dispatched tools, including built-ins, MCP and the future browser c7-c9, map to _effects.prepare@1. The model-dispatch tool and local-effect tools are never offered. tool_contract_versions equals exactly the set of offered tool refs. (2) The Responses adapter maps each function_call by name to the unique offered definition and emits a typed ModelToolProposal: tool, operation_id and operation_version come from the definition, and source_context is the action's context_artifact. This works on both Invoke and Reconcile. It emits no proposal for an unoffered or unmapped tool, non-object arguments, or a duplicate call id; each of those gets a typed flag instead. (3) Execution refuses a proposal with zero effects when: - its mapping differs from the pinned component mapping; - it names an unoffered component or the model tool; - it is a model-chosen local operation. (4) A reply on a conversation-linked turn is delivered exactly once: - it is prepared as conversation.message.send with a deterministic message_id; - it is driven through WorkerOperator.ExecuteWorker under the worker's own actor; - it is recorded through _execution.proposal.record, which completes the turn; - only after that record succeeds is the matching preview committed. Message turns adopt their conversation. Human recipients are never admitted as turns or auto-acknowledged. (5) render.py --check, sync_mcp_runtime.py --check and the specgen unittests pass at revision 21. (6) tests/integration/hosted_turn_test.go asserts typed proposals instead of the gap. (7) The end-to-end persisted-reply integration test is green once the separate gap-0 connection-validation fix lands. That fix is outside E0T.
