## Current blockers and exact gaps

- **Serenity (hard upstream dependency):** the local source checkout is clean at `b4febdf` and matches Zatiti's pin. It implements metadata at `/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource`, dynamic registration at `POST /oauth/register`, PKCE authorization at `GET /oauth/authorize`, token/refresh at `POST /oauth/token`, revocation at `POST /oauth/revoke`, and project-scoped MCP. It does not expose a bearer-authenticated binding read that jointly proves stable account, selected project, effective scopes, grant and live revocation/project state. Its current `recall`, `remember`, `entity`, `synthesize`, and `forget` MCP surface also does not yet prove Zatiti's required provenance/freshness, bounded cost/disclosure, lost-ack status reconciliation, or immutable revision export/restore. Local source tests and synthetic empty memory are not deployed hosted-service evidence.
- **Zatiti OAuth/memory:** `internal/connections/localio.go` consumes pre-supplied challenge metadata rather than doing discovery/registration/PKCE/callback/token lifecycle. `internal/adapters/serenity` refuses physical operations and reconciliation. `internal/execution/context_build.go` fails closed when configured recall is incomplete; completed governed recall is not yet part of the immutable model context. These are explicit code gaps, not merely a request for credentials.
- **Provider:** OpenAI, OpenRouter and Experiential Labs adapters and the desktop model/profile workflow have controlled tests. There is no real installed Desktop → controller → provider → durable conversation readback/restart result. The existing opt-in live test is OpenAI-specific and is not evidence for OpenRouter or Experiential Labs. `TestOpenRouterProfileQualificationProbe` now provides the P1 OpenRouter probe step: one opt-in, fixed-prompt request for an explicitly selected model and single pinned route with an enforced price ceiling, reading the key from a named Keychain item. It has not been run against the provider, and its offline companion test checks only that the adapter accepts the probe's profile and action. The current qualification root has no driver to securely set up a profile in the installed helper, drive the installed Desktop/controller across restart, or verify physical-call evidence and counts. Adding an adapter-only live request would not satisfy the product gate. The exposed Experiential Labs credential must be rotated before any use; its prior value must not be reused.
- **Mac:** this Intel machine has valid Developer ID Application and Installer identities. Notarization credentials/profile were not verified. No signed/notarized final packages or bootstrap are present, and `liveMacHostDriver` is unregistered. Release CI validates unsigned candidates and blocks a passing report without release evidence, but has no signing/notarization producer stage or clean-host runner route. Its native macOS runners include developer tools and cannot satisfy the clean-host case. Native Apple Silicon CI builds/tests source but does not install the release on a clean host. Consequently both Intel and Apple Silicon install-to-first-chat remain unqualified.

Until these gates pass, keep the draft PR and README marked pre-release and do not publish a supported install command. iOS, Android, web, Linux, and Windows remain later qualification tracks.

### Streaming replies and phrase speech (revision 20)

Revision 20 adds live previews of the worker's `reply` tool text and phrase-by-phrase speech. It is source work only; none of it is qualified.

- **What exists in source.** The Responses adapter requests a stream only when a reply route is registered for the step's context and the protocol documents Responses streaming events (OpenAI and OpenRouter; not Experiential). Only reply-tool text is previewed. Free text, reasoning and other tool arguments are never published. The controller hub scopes previews to the requesting human, installation and conversation. `POST /v1/replies/stream` reauthorizes `conversation.message.list` before every frame. `voice.speak.phrase` speaks one append-only phrase that the controller resolves; the client never supplies the text. A second command for the same phrase is refused before accounting. In a voice session, execution pins Narrate's craft instructions into the persisted model context, so no second rewrite call is made.
- **What is tested.** Go unit and fixture tests cover phrase stability as text grows, recipient scoping, reconnect snapshots, chronological preview order, eviction of the oldest entries when the hub is full, sentence release for scripts without spaces, provider interruption, preview faults that must not fail the model step, commit only after a recorded reply with the same text (including the real proposal lookup after interpretation advances the turn version), duplicate-phrase refusal by phrase rather than request bytes, `voice.speak.phrase` routing through the assembled application, settlement of stale voice calls, no-charge billing for requests that never left the machine, reply streams ending on server shutdown, and craft injection bound to the newest voice session. Flutter tests cover stream parsing, reconnect, the spoken-phrase queue (dedupe, barge-in, withdrawal of an interrupted attempt, and a retry that speaks phrases the interrupted attempt never played) and preview labels. All provider streams in these tests are synthetic.
- **What is not established.** No live provider stream has been exercised; OpenAI and OpenRouter streaming are enabled from their documented contracts only. The end-to-end hosted reply path is still blocked upstream: the Responses adapter does not yet map tool calls to typed proposals (`tool_proposal_mapping_unspecified`), and a recorded `reply` proposal is not yet delivered as a durable conversation message. Until those land, a preview marked committed is shown as "live preview only, not in history yet", and previews are lost after 10 minutes or a controller restart. Native audio qualification (V4) also covers phrase playback, interruption and prefetch.
