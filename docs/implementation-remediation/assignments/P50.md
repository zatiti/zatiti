## What is actually broken today

Confirmed by reading the landed code, not inferred:

- `internal/controller/restore.go`'s `RestoreLifecycle` interface declares `StageCandidate(ctx, restoreJobID, dir) (RestoreCandidate, error)` and `MergeOverlay(ctx, u contract.Unit, restoreJobID) error`. `cmd/zatiti/restore.go`'s `restoreLifecycle{}` — the only production implementation — is an empty struct whose two methods unconditionally return `errNoCandidateLookup`/`errNoOwnerMerge`, both `contract.CodePrerequisiteMissing`.
- `cmd/zatiti/restore.go`'s own package doc (lines 1–72) already diagnoses why: "There is no operation, public or internal, that returns a pending restore job's original backup-artifact reference... and no owner-defined merge operation exists in internal/effects, internal/identity or internal/memory to fold a RecoveryOverlay's obligations back into their own tables." It also records that duplicating `internal/installation`'s backup-bundle crypto in `cmd/zatiti` "was considered and rejected without explicit sign-off" because it would create a second, un-synced AEAD implementation.
- `internal/installation/restore_test.go`'s `TestRestoreOverlayPreservesPostBackupUnknownEffectAcrossRewind` doc comment states outright that a credential/grant revocation "cannot be exercised here because no owner port installation may call enumerates current revocations" — confirmed by reading `internal/installation/backup.go`'s `snapshotObligations` (lines 174–225): it only classifies pending effects (`claimed_effect`/`unknown_effect`) and memory obligations (`memory_write`); revocations are never captured into a manifest or overlay in the first place, so even a working `MergeOverlay` would have nothing to merge back.
- `internal/controller/restore.go`'s `restoreClaim` (lines 322–339) already calls `_execution.job.claim` and captures the pending restore job's original input into `e.JobInput` — but `performSwap` (lines 366–418) never passes it to `StageCandidate`. The data half of gap 1 is already fetched and thrown away; only the plumbing is missing.
- `internal/installation/restore.go`'s `finishRestore` (lines 355–412) records the published recovery-overlay artifact's reference as a `wireRequirement{Code: "recovery_overlay_published", ..., ResourceID: &overlayID}` on the job's own **local** `jobRow.Requirements` (`internal/installation`'s private table) — never on the shared `execution_jobs` row `_execution.job.claim` reads. So even with a working merge operation, nothing today tells `MergeOverlay` which overlay artifact to fetch and decrypt.
- `MergeOverlay` receives `u contract.Unit` from `internal/storage/restore.go`'s `WriteRestoreOverlay` (a raw storage-layer write transaction opened directly against the freshly reopened database) — **not** from `internal/application`. At this exact point in the controller's lifetime, `c.app` (the `*application.Application` this Controller was constructed with) is already permanently stale: `CommitRestore` closed the database handle it was built over (see `internal/controller/restore.go`'s own package doc, lines 36–51), and `cmd/zatiti/assembly.go`'s `reassembleAfterRestoreHandoff` only rebuilds a fresh `Application` **after** this whole `runRestore` call returns `controller.ErrRestoreHandoff`. `internal/application/dispatch.go`'s `Internal` (lines 140–186) and `dispatchNested` (lines 261–309, specifically the `stateFrom(ctx)`/`sameUnit` checks) both require an already-open `Application`-managed dispatch chain. So `MergeOverlay`'s owner-merge calls structurally **cannot** go through `Application.Internal` or the `contract.Ports`/`callPeer` mechanism `internal/installation/peer.go` already uses elsewhere — there is no live `Application` to route through at that moment. This is not a missing binding; it is why the original P33 implementer correctly left this unsolved rather than inventing a broken seam.

## The design

**Gap 1 — StageCandidate (backup artifact → decrypted local file).** No new frozen operation. `installation.backup`/`installation.restore`'s own `performRestore` (`internal/installation/restore.go`, lines 227–261) already runs this exact pipeline — `readPublished` → `decodeArtifact` → resolve the backup key via `contract.SecretStore` → `openBackupBundle` — entirely outside any `contract.Unit`, using only `contract.SecretStore`/`contract.BlobStore`, which `cmd/zatiti` already holds directly (`h.plat.Secrets()`/`h.plat.Blobs()`). Export a narrow wrapper, `installation.ResolveBackupCandidate(ctx, secrets, blobs, installationID, artifact, size, destDir)`, around the existing **unexported** `readPublished`/`decodeArtifact`/key-resolution/`openBackupBundle` pipeline, so `cmd/zatiti` never reimplements AEAD framing. Plumb the backup artifact reference to it by extending `RestoreLifecycle.StageCandidate`'s Go signature to accept the job input `restoreClaim` already captures (`e.JobInput`) — a Go interface change, not a wire contract change.

**Gap 2 — MergeOverlay (owner tables).** Requires three new frozen internal mutations — `_effects.restore.merge`, `_identity.restore.merge`, `_memory.restore.merge` (each `visibility: internal`, `mode: mutation`, `callers: ["controller"]`, mirroring `_installation.restore.record`'s existing convention) — because writing into another owner's tables must go through that owner's own `Bind[I,O]`-registered, schema-validated handler, never raw cross-package SQL. Because no live `Application` exists at `MergeOverlay` time (see above), these are **not** dispatched through `Application`/`Ports`. Instead, `cmd/zatiti`'s `restoreLifecycle` holds direct `contract.Module` references to the already-constructed `effects`/`identity`/`memory` services (selected from `modules()`'s returned slice at assembly, exactly as `addJobRunner` already selects `contract.LocalJobRunner` implementers) and calls `Handle(ctx, u, invocation)` on each **directly** — the same `Bind`-produced handler that validates schema and dispatches by operation ID, just invoked without `Application.Internal`'s wrapping transaction and centralized caller check. Because that centralized check is bypassed, each new merge handler must **defensively verify `unit.Actor()` names the controller's own service principal** before writing (mirroring `internal/identity/internal_ops.go`'s `requireLiveActor` pattern) — this is a required behavior, not an optional hardening, and needs its own test (see below).

Two supporting gaps close alongside this:
- `_identity.revocations` (new internal query, owner `identity`, `callers: ["installation"]`) lets `internal/installation`'s `snapshotObligations` actually capture current credential/grant revocations into `manifestObligation` (new `Kind` values `revoked_credential`/`revoked_grant`) — without this, backups and overlays never carry revocations to merge in the first place, exactly the gap `TestRestoreOverlayPreservesPostBackupUnknownEffectAcrossRewind`'s doc comment names.
- `_installation.restore.overlay` (new internal query, owner `installation`, `callers: ["controller"]`) exposes the recovery-overlay artifact reference `finishRestore` already records locally, so the controller can fetch it **before the swap** (while `c.app`/`c.call` are still valid) and journal it on the entry (`OverlayArtifact`, alongside the existing `JobID`/`JobInput`) so it survives a crash exactly as those fields already do, and is available to pass into `MergeOverlay` after the swap.

## Implement in this order

1. Extend the frozen contract via `tools/specgen/model.py` (never hand-edit `operations.json`): add `_effects.restore.merge`, `_identity.restore.merge`, `_memory.restore.merge` (internal mutations, `callers: ["controller"]`); add `_identity.revocations` (internal query, `callers: ["installation"]`); add `_installation.restore.overlay` (internal query, `callers: ["controller"]`). Regenerate assignments/fixtures; run `python3 tools/specgen/render.py --check` before any downstream step starts.
2. `internal/identity`: implement `_identity.revocations`; implement `_identity.restore.merge` to re-apply (never lift) named credential/grant revocations monotonically — never resurrecting a revocation newer than the overlay's own capture point — and idempotently under a repeated call with the same restore job's obligations.
3. `internal/effects`: implement `_effects.restore.merge`, folding `claimed_effect`/`unknown_effect` obligations back into effects' own tables — never resurrecting a completed dispatch, never resending a consumed one, idempotent under replay.
4. `internal/memory`: implement `_memory.restore.merge`, folding `memory_write` obligations back into memory's own tables, idempotent under replay.
5. `internal/installation`: (a) call `_identity.revocations` from `snapshotObligations`/`prepareBackup`/`prepareRestore` and add `revoked_credential`/`revoked_grant` obligation kinds; (b) implement `_installation.restore.overlay` by promoting the overlay artifact reference `finishRestore` already writes into the local `jobRow.Requirements` to a typed field the new query reads directly; (c) export `ResolveBackupCandidate` and `OpenRecoveryOverlay` — thin wrappers taking no `contract.Unit` — around the existing unexported decrypt/verify pipeline.
6. `internal/controller`: (a) extend `RestoreLifecycle.StageCandidate` to accept the restore job's original input (`json.RawMessage`) — `restoreClaim` already captures it via `_execution.job.claim` into `e.JobInput` and currently discards it; (b) add `OverlayArtifact` to the journal `entry`, populated in `restoreClaim` via the new `_installation.restore.overlay` call in the same pre-swap window as the existing `_execution.job.claim` call; (c) extend `RestoreLifecycle.MergeOverlay` to accept that overlay reference; (d) thread both through `performSwap`'s and `mergeAndResume`'s existing call sites.
7. `cmd/zatiti`: (a) give `restoreLifecycle` real fields — the already-available `contract.SecretStore`/`contract.BlobStore`, plus direct `contract.Module` references to the constructed `effects`/`identity`/`memory` services from `modules()`'s returned slice; (b) `StageCandidate` decodes the backup artifact reference from the passed job input and calls `installation.ResolveBackupCandidate` directly; (c) `MergeOverlay` calls `installation.OpenRecoveryOverlay` with the passed overlay reference, buckets the decoded obligations by `Owner`, and calls each owner `Module`'s `Handle(ctx, u, Invocation{Operation: "_owner.restore.merge", ...})` directly — never through `Application`/`Ports` — with each new merge handler independently re-verifying `unit.Actor()`; (d) delete `errNoCandidateLookup`/`errNoOwnerMerge` and their fail-closed stubs.

## Required behavioral tests

- A real `installation.backup` followed by domain mutation (a newly accepted task, a new effect dispatch, one credential revocation and one grant revocation) followed by `installation.restore` to the earlier backup drives an actual controller swap; the resumed installation reads the backed-up task/effect state but the post-backup credential and grant remain revoked — the exact behavior `TestRestoreOverlayPreservesPostBackupUnknownEffectAcrossRewind`'s doc comment names as currently unexercisable.
- Killing the process between a successful `StageCandidate`/`CommitRestore` and a completed `MergeOverlay`, then restarting, resumes from the journaled phase and finishes without re-decrypting the backup bundle or double-applying any merged obligation; repeating `MergeOverlay` against an already-merged state asserts no duplicate effect/revocation/memory rows.
- Calling `_effects.restore.merge`, `_identity.restore.merge` or `_memory.restore.merge` with a non-controller actor is refused; `StageCandidate` and `MergeOverlay`'s `cmd/zatiti` implementations are exercised against a real published, encrypted backup bundle and a real sealed overlay artifact, never a fake or an in-memory shortcut.
- Backup and restore of an installation with zero pending obligations still succeeds (nothing to merge is not an error), and `_identity.revocations` reports zero revocations when the installation was bootstrapped and never restricted.
