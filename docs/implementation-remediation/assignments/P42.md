Implement in this order:

1. Use identity.current and conversation.message.list instead of optional principal config and window-only sent history.
2. Persist selected conversation, bounded authorized cache and unsent drafts in OS-protected local storage; credential remains only in secure storage. Revalidate cache on revocation/account switch.
3. Render turn acknowledgement, working, clarification, blocked setup, review waiting, error and final reply using controller state, never a fabricated local response.
4. Implement real unread/preview/quiet-coordination behavior and resumable event cursors; offline/reconnect sends nothing automatically.
5. Provide a secure remote TLS profile import flow if remote desktop remains supported.

Required behavioral tests:

- Send to chief, close/reopen app: both messages and real reply remain, with correct read state.
- Offline draft/reconnect preserves original submission identity and creates no duplicate turn.
- Account/scope switch does not leak cached history; unsupported controller shows a named state.
