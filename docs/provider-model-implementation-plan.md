# Provider and model selection implementation plan

Planning date: 2026-09-24. This is an implementation assignment, not executed qualification or a claim that the installed desktop works. Plan with Astra; implement the packets below with Luna. One integration owner lands changes. Existing uncommitted edits to `README.md`, `apps/desktop/README.md`, `docs/rfc.md`, and `packaging/README.md` belong to the user and must be preserved.

## Intended result

The desktop can create/configure an OpenAI, OpenRouter, or Experiential Labs connection, capture its credential through the existing secure local helper, select a model for a worker (including the personal chief), and save that selection through authenticated controller operations. The controller persists the selection across restart and uses its exact version for subsequent turns. A real chief conversation receives a model reply. Existing OpenAI behavior remains supported. OpenRouter's initially selected model is exactly `z-ai/glm-flash-latest`; do not silently substitute another model if it is unavailable.

Implementation must include controlled tests for all providers and a real installed-controller/desktop OpenRouter journey when credentials and provider availability permit. The user intends to add `EXPLABS_API_KEY` to the ignored `.env`; run a bounded Experiential live smoke check when it is present. Its absence does not block implementing or fixture-testing Experiential. A successful HTTP smoke call alone does not qualify the application's full conversation loop, accounting, recovery, or desktop.

## Verified starting points and blocking seams

* `internal/adapters/responses/protocol.go` already provides a protocol abstraction, but only registers OpenAI. `openai.go` uses a preparatory conversation request and conversation-item reconciliation. Do not implement a gateway by changing the OpenAI base URL.
* `docs/implementation/adapter-schemas.json`, `internal/adapters/responses/action.go`, `wire.go`, and `internal/connections/builtin_tools.go` require a nonempty `session_handle` on every model step. The same requirement exists in evidence. `internal/execution/turn_ops.go:dispatchModelEffect` unconditionally prepares a session when the handle is empty.
* `cmd/zatiti/adapters.go` loads one startup-only `responses.json`. That is not a durable, per-worker provider/model registry. A desktop preference or rewriting this global file would silently mismatch worker profiles, active runs, and recovery.
* `ExecutionProfile` in `tools/specgen/model.py` and configuration DTOs already belongs to the definition/compiler system. Reuse that ownership; do not introduce an independent settings database.
* `internal/execution/turn_ops.go:handleContextCommit` dispatches only task-bound turns. Its model effects currently use a zero cost bound. `context_build.go` guesses connection/tool version 1 and output limit 4096. Resolve actual versions and profile limits instead.
* `internal/controller/turns.go` currently emits `zatiti.controller.context-plan/v1`, while the adapter requires a complete `zatiti.context/v1`. Execution has a private `stageContext` implementation that needs a supported perform seam. Exposing the real context preparation path is required, not optional cleanup.
* `apps/desktop/lib/src/ui/workspace_settings.dart` lists existing connections and can capture a key, but cannot create/select provider/model configuration. `state/installed_chief.dart` correctly requires a committed profile, validated connection, and effective budget. Preserve that honesty.

## Primary protocol findings

OpenRouter exposes `POST https://openrouter.ai/api/v1/responses`, `store:false`, output token limits, function tools, routing options, and a `session_id` used for grouping/sticky routing. A session label is not a conversation resource, replay key, or proof of execution. The first implementation uses explicit stateless transcript replay and no automatic reconciliation of a lost response. Its generation lookup requires a received generation identifier, so it cannot resolve an unknown request that lost that identifier. References: [Responses endpoint](https://openrouter.ai/docs/api/api-reference/responses/create-responses), [generation lookup](https://openrouter.ai/docs/api/api-reference/generations/get-generation).

OpenRouter has provider allowlists, fallback controls, parameter support enforcement, and price filters. Pin the permitted provider route when enabling an enforced profile; `allow_fallbacks:false` alone is not proof of exactly one upstream execution or a total request price ceiling. A latest-model alias can change its resolved model, capabilities, and price. Record requested and returned model identities and refresh evidence before treating old qualification as applicable. References: [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection), [usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting).

Experiential serves Responses at `https://api.experientiallabs.ai/v1/responses`. Its documented gateway controls can restrict a request to one generation dispatch: `gateway.retry.max_attempts_per_route:1`, `max_total_attempts:1`, `backoff:{type:"none"}`, and `gateway.routing.allow_fallbacks:false`; an authenticated route handle can pin an exact route. These are distinct from its forwarded `provider` preferences. Reference: [waterfall controls](https://platform.experientiallabs.ai/docs/waterfall).

Experiential can disclose dropped fields through `x-experiential-ignored-parameters`; dropped tool or bounding controls must not be accepted as qualified behavior. First implement stateless full context replay, with no stored continuation dependency. Do not claim `store:false` disables organization prompt capture: content capture and continuation storage depend on account data controls. References: [OpenAI compatibility](https://platform.experientiallabs.ai/docs/openai-compatibility), [data controls](https://platform.experientiallabs.ai/docs/data-controls).

Experiential reports inline USD cost, gateway request IDs, and serving provider identity. Its BYOK platform cost can be zero while an upstream charge remains. Treat platform and upstream costs separately and never infer free inference from a gateway zero. References: [cost API](https://platform.experientiallabs.ai/docs/cost-api), [model catalog](https://platform.experientiallabs.ai/docs/models). The [public repository](https://github.com/experientiallabs/experiential) is supplemental evidence, not proof that the hosted deployment matches a particular commit.

Before pinning either new protocol revision, save document/source revision identifiers and fixture provenance in `internal/adapters/responses/PROTOCOL.md`. Record separately what is documented, fixture-tested, and live-observed. Do not label a protocol live-qualified merely because it appears in the protocol dispatch table.

## Stage 1 — serialized contracts and foundation

No dependent implementation packet starts until this baseline lands. Read each affected directory's generated AGENTS before implementing. Author changes in `tools/specgen/model.py`, `tools/specgen/packages.py`, `docs/implementation/contracts.md`, `adapter-schemas.json`, `requirements.json`, and `acceptance.json`; bump coordinated revision 11 to 12 in the model and contracts title. Run `python3 tools/specgen/render.py` then `python3 tools/specgen/render.py --check`. Never edit generated AGENTS or operation catalogs by hand. No new dependency is expected; if one proves necessary, pin it and update the dependency lock in this serialized assignment.

Freeze these concrete additions before dispatch:

1. **Versioned Responses schemas.** Add `zatiti.responses/v2`, `zatiti.responses.action/v2`, and `zatiti.responses.evidence/v2`; continue decoding existing v1 profiles/actions/evidence so recorded operations and OpenAI fixtures remain recoverable. V2 profile adds `provider` (`openai|openrouter|experiential`), `session_mode` (`provider_conversation|stateless`), and strict provider-specific `routing` objects. Preserve existing endpoint/model/connection/token/byte/time/currency/rate/enforcement/capability fields. Provider and protocol revision must agree. OpenAI initially retains `provider_conversation`; the two gateways use `stateless`.
2. **Session action discriminator.** V2 model action has `session_mode`. The conversation branch requires nonempty `session_handle`; stateless forbids `session_handle` and `continuation_reference`. Optional `session_id` is a bounded, controller-generated grouping label only, derived from the turn/conversation identity without secrets or prompt text. `prepare_session` is permitted only for a conversation profile. V2 evidence makes the same distinction. No fake empty or locally generated provider handle. Preserve exactly one physical request per adapter invocation.
3. **Durable executable configuration.** Extend hosted `ExecutionProfile` with optional-on-read `adapter_profile` referencing the strict Responses v1/v2 schema, and `connection_version` (positive integer). New editable hosted profiles require these; legacy definitions lacking them remain readable and require explicit import/resolution before new dispatch. Existing `model`, `connection_id`, `provider_destination`, and `cost_bound` must agree with the nested profile. Immutable old profile versions remain available for pending operations. Bind capability evidence to the complete adapter-profile digest; changing model/route/endpoint/rates invalidates that evidence.
4. **Pinned dispatch configuration.** Add optional `execution_profile` VersionRef to hosted model Action and optional `adapter_profile` raw JSON to trusted Dispatch. Add `_configuration.execution_profile.resolve` (query; allowed callers `execution,effects`; scoped exact VersionRef input; complete profile output). Effects resolves and validates the version during preparation, persists the exact secret-free adapter profile with the operation, and returns it on claim/reconciliation. It rechecks current connection authority before sending. Public callers cannot inject arbitrary dispatch JSON. The controller constructs/caches a Responses adapter from that pinned config outside the transaction. It never resolves a newer worker setting for an old operation.
5. **Canonical context perform seam.** Add a narrow `ContextPerformer` contract implemented by execution: `PerformContext(ctx context.Context, plan ContextPlan) (json.RawMessage, error)`, returning the already-defined ArtifactLocator wire object. The exact Go `ContextPlan` fields mirror the frozen wire plan. It reads the persisted immutable execution recipe, builds/validates/stages the complete context outside a write Unit; `_execution.context.commit` performs generation/current-authority checks and publication bookkeeping. Inject this performer into controller dependencies. Reuse execution's actual `stageContext`; delete the controller placeholder context path after wiring succeeds. Do not grant a model-callable context IO operation.
6. **Turn observation without a task.** Add `_execution.turn.observation` (mutation; caller `controller`; input `turn_id,step_index,operation_id,observation`; output WorkerTurn). It authenticates the persisted effects callback route, fences turn generation/step, and is idempotent by operation ID. Task-bound compatibility can delegate to the same logic; task success still requires its existing verifier. Chat never fabricates an Attempt or task acceptance.
7. **Provider metadata and configuration operations.** Add `model.provider.list` (authenticated query owned by connections; scoped input; provider ID, display name, fixed default endpoint, supported session mode, credential setup mode). Use existing execution-profile/worker definition draft → validate → plan → apply operations for saves. Model selection initially supports named configured profiles plus a validated model-ID field; a live searchable catalog is not required for this scope. Add exact provider-specific validation to the existing `connection.validate` job; do not do HTTP inside a database transaction. Validation of a credential is distinct from qualification of a model/route profile.
8. **Accounting additions.** Extend normalized provider usage/evidence with optional requested/served model, serving provider, provider request ID, and exact decimal cost provenance. Existing `Usage` integer micro-units remains the ledger unit. Specify decimal-to-micro conversion with checked integer/rational arithmetic and upward rounding; retain the source decimal as evidence. Cost absence, invalid decimal, overflow, disputed route, or unpriced BYOK upstream remains unknown/advisory. Add no floating-point money calculations.

Strict `routing` profiles: OpenRouter initially allows a bounded `only` provider list, `allow_fallbacks:false`, `require_parameters:true`, optional price ceilings and documented privacy constraints. Experiential uses the single-attempt gateway object described above, optional authenticated `route_id`, and separately declared privacy constraints. Unknown routing keys fail. Endpoint host/path allowlists stay fixed for these presets; a user model string cannot select an arbitrary URL or enable plugins. Reject provider-specific settings on the wrong provider.

Update affected schema copies in implementation, including package DTOs/schema literals, builtin Responses tool versions, Go contract schemas, and Dart wire types. New tool schema gets a new immutable tool version; do not overwrite an old version still pinned by existing operations. Configuration, effects, execution, controller, connections, adapters, desktop, and tests are affected callers. Retain current acceptance requirements and add cases; do not weaken unknown-outcome or hard-cap gates.

## Stage 2 — bounded Luna packets

Use fresh worktrees based on the landed foundation for concurrent packets, with no root/foundation writes while descendants are active. Serial packets in the same checkout are also valid. Each packet returns changed files, tests actually run, and unresolved limitations. Do not ask Luna to improvise missing shared contracts: report omissions to the integration owner, revise serially, then resume.

### L1: Responses protocols and cost evidence

Root: `internal/adapters/responses` only. Add `openrouter.go`, `experiential.go`, protocol tests and fixtures; update `protocol.go`, `profile.go`, `wire.go`, `action.go`, `adapter.go`, `interpret.go`, `evidence.go`, `bounds.go`, schema embeds, and `PROTOCOL.md` as needed.

* Encode bounded nonstreaming Responses requests with the exact selected model, complete context, normalized function tools, max output tokens, `store:false`, no background work, no provider-hosted tools/plugins/search, no automatic continuation or retries. Shared text/tool conversion helpers are acceptable; separate provider policy and decoding remain explicit.
* Skip session preparation for stateless profiles. Set `SupportsReconcile=false` initially for gateway protocols. Sent/possibly-sent timeout, partial body, malformed success body, cancellation, or lost ID stays unknown. A metadata/cost lookup must never stand in for recoverable model output or prove nonexecution from absence.
* Normalize completed, tool-call, refusal, incomplete/length, provider error, and usage outputs. Preserve input/output/reasoning/cache evidence, served model/route, and optional billed cost. Parse money from `json.Number` or raw decimal, never float64. Check safety-critical ignored-parameter disclosures.
* Keep the existing admission behavior: enforced mode requires demonstrated input/output/price bounds; otherwise return an explicit capability failure. Advisory mode is visibly advisory and can run only under existing authority that permits it. Do not promote documentation-only price assumptions to a hard cap to make a live test pass.
* Test exact endpoint/auth/header/body selection, no `/conversations` request for either gateway, one send on every failure, no redirects, response/body bounds, secret redaction, malformed costs, unknown usage, BYOK cost ambiguity, routing changes, dropped bounds, tool-result replay, and unchanged OpenAI preparation/reconciliation.

### L2: Durable configuration, provider connection setup, and dispatch profiles

Serialize the roots `internal/configuration`, `internal/connections`, and `internal/effects` within this packet (or dispatch as disjoint agents only after exact interfaces are landed). Implement stage-1 persistence and resolvers, provider metadata, authenticated saves through existing changesets, real provider-aware connection validation, and immutable dispatch profile snapshots. Add migrations only in the owning root.

There is no credential text field in ordinary operation JSON. Reuse `connection.setup.*`, `platform.SecretStore`, and the installed local capture helper. Provider/account changes must not reuse an old credential or validation state. Freshness and current revocation checks continue to apply. Treat a catalog response as model availability evidence, not account identity proof; document each provider's available identity evidence rather than fabricating account IDs.

Provider/model UI changes create/update execution profiles and worker assignments atomically through the existing compiler plan. Validate all duplicated profile fields, exact connection version, provider routing, capability evidence, classification/disclosure, and current policy. Keep an existing profile usable until a replacement successfully commits. Active turns retain old versions; changing provider/model applies at the next turn and cannot mutate an in-flight session.

Tests: restart persistence, stale-version conflicts, denied caller, revoked connection, profile digest mismatch, endpoint mismatch, cross-provider credential confusion, replayed save, new profile version versus active operation, exact historical profile recovery. Use synthetic identities and public endpoints.

### L3: Real context and chief-chat loop

Root: `internal/execution`. Wire the context performer, read actual profile limits and pinned versions, and eliminate fallback guesses for dispatch. Dispatch stateless model steps directly for both task and non-task turns. For OpenAI preserve prepare-then-step, persistence, and unknown prepare semantics.

Reserve a real maximum cost for each model step via effects/accounting, taking the profile and remaining turn budget into account. Preparation alone may have zero only when documented free. A GUI selection cannot create budget authority; existing setup requirements remain until a spend/step limit is committed.

Implement turn-keyed callback handling, provider-output persistence and conversation publication, function tool proposals/results, and subsequent context replay. Include actual earlier user/assistant/tool exchanges in stateless context; never send only the most recent input after a successful tool call. Keep reasoning continuity limitations explicit. Ensure a model step is not duplicated after controller restart, callback replay, or a lost acknowledgement. Unknown outcomes stop that turn with a visible unresolved status.

Tests: ordinary chief chat without an Attempt, task-bound OpenAI regression, two stateless conversational turns, tool call → governed execution → result → answer, output limits from the chosen profile, budget refusal before send, profile switch at a turn boundary, duplicate callback, restart at each dispatch boundary, and unknown outcome without replay.

### L4: Controller and entrypoint integration

Roots serially: `internal/controller`, then `cmd/zatiti`. Inject the context performer and use persisted callback routes for both chief chat and tasks. Build/cache Responses adapters by canonical pinned profile digest for invoke and recovery; do not mutate one global adapter when a worker selection changes. Avoid shared-map races. Other adapters keep their current behavior.

Keep legacy `adapters/responses.json` support only as an explicit compatibility/import source. Never silently make it override a durable worker profile. For installed empty-state setup, create the configured connection and profile through authenticated operations and the compiler; source credentials only from the existing secure helper. New hosted profiles must work without controller restart.

Tests: multiple workers using distinct providers concurrently, profile changes without restart, exact old-profile recovery after restart, unavailable profile error, current credential revocation, and successful end-to-end chief reply through a local synthetic HTTP server. Do not mark runtime ready from successful startup alone.

### L5: Desktop provider and model selection

Root: `apps/desktop`. Update `api/models.dart`, `api/controller_api.dart`, `transport/operations.dart`, `state/workspace_source.dart`, `live_source.dart`, `workspace_controller.dart`, `snapshot.dart`, and UI files as needed; keep demo and live implementations distinct.

In workspace settings add a usable empty-state **Add provider** flow, provider dropdown (OpenAI/OpenRouter/Experiential Labs), named connection, secure **Set API key** action, validation state, and model/profile selection for the personal chief. Reuse the same editor in worker details. Show the active provider and model near the conversation composer; default the OpenRouter model field to the exact user-selected ID. Existing configured profiles appear as options; editable model ID allows additional provider models without shipping an unsupported all-model catalog promise.

Save runs the normal draft/validate/plan/apply controller sequence and refreshes authoritative worker state. Render saving/error/stale-conflict states; a local dropdown value is not proof of an applied selection. Failed save keeps the previous active label. Show missing key, unvalidated model/profile, advisory cost, and unresolved response states plainly. Explain that a change applies to the next turn. Disable send for genuine unmet controller prerequisites, not merely because this client lacks a cached selection.

The UI must let the user finish setup from an empty connection list. Do not expose raw adapter JSON, capability digest editing, or provider secrets as normal product form fields. Advanced route controls may remain behind a details panel; build/profile qualification status must come from controller evidence, not a user tick box. Credential capture stays outside chat and logs.

Tests: empty-state provider creation, all three provider options, exact OpenRouter model string, save/reload/restart, worker-specific selection, stale/denied save, missing credentials, secure capture invocation, selected label reflecting acknowledged state, pending turn preserving old selection, and actual reply appearing in the conversation.

## Stage 3 — integration, installed application, and qualification

Integration owner lands packets in dependency order: foundation → L1/L2 → L3 → L4 → L5 → integration and qualification. No need to parallelize if worktree overhead makes serial implementation clearer. Every implementing agent uses Luna as requested.

Run focused Go tests per packet, then `go test ./...` after integration; run race checks on affected stateful packages. Run `python3 tools/specgen/render.py --check`, repository schema/parity tests, `flutter analyze`, and `flutter test` from `apps/desktop`. Build the actual platform bundle using the repository's existing packaging instructions. Inspect failing tests rather than broadly regenerating snapshots to hide schema drift. Planned/skipped tests and compilation are not release evidence.

Add cross-package tests in `tests/integration` and provider/installed-desktop checks in `tests/qualification`. Test the real authenticated operation transport, database, adapter dispatch, context artifacts, message projection, and desktop state together; fakes at internal owner boundaries alone cannot prove this path. Include migration of legacy OpenAI records and both old/new schema replay.

For live qualification, load authorized keys from the ignored `.env` into a child process without printing values or placing keys in command-line arguments, fixtures, evidence, or logs. Do not display or `cat` `.env`. Use `OPENROUTER_API_KEY` for the selected OpenRouter profile; use OpenAI credentials only within the authorized task. If `EXPLABS_API_KEY` is absent, record Experiential live checks as not run and continue all controlled checks.

First perform bounded provider metadata/profile qualification and one synthetic request. Record actual model availability, returned model/route identity, usage and cost behavior, and any unsupported bounding control. Do not retry a possibly-sent request merely to obtain cleaner evidence. A protocol that cannot meet an enforced-cost contract stays unavailable in enforced mode; do not invent an enforceability claim. If an explicitly permitted advisory configuration is used, name that limitation in the GUI and qualification report.

Then exercise the actual installed build: open settings from an empty or existing connection list, select OpenRouter and `z-ai/glm-flash-latest`, capture/import the authorized key securely, save a valid profile and existing approved budget configuration, send a synthetic chief message, receive a real answer, restart controller/desktop, and verify selection and conversation persistence. Repeat a model/profile switch and confirm it affects only the next turn. Validate a function-tool round trip where supported. Retain redacted evidence with build IDs and exact tests run. Do not commit personal paths, private account identifiers, request content, or credentials.

If a provider is unavailable or credentials are missing, finish the implementation and clearly distinguish fixture evidence, live smoke evidence, and the installed end-to-end journey. Do not claim full provider parity, release qualification, or an Experiential live pass from controlled tests. Report a concrete remaining prerequisite instead of leaving a cosmetic selector labeled complete.

## Completion checklist

* All three protocols are explicitly selectable; OpenAI compatibility/recovery tests pass.
* Gateway calls have no conversation-creation dependency, do not retry unknown outcomes, and preserve real usage uncertainty.
* Provider/model configuration is versioned, authenticated, durable, and consumed by dispatch; historical operations use historical profiles.
* The chief chat performs real complete-context model dispatch without a fabricated task, applies real budgets, and projects confirmed replies.
* The desktop can complete provider setup from empty state and shows the acknowledged provider/model after restart.
* Controlled tests cover each provider and failures. Live and installed evidence is recorded separately, including anything not run.
* Generated specifications are fresh and user-owned marketing edits are intact.
