## The six defects, and why they matter more than the features

Five of the six were invisible until another fix let a test reach them. Two
integration tests had been skipping for a day; the moment they ran, they
found real bugs. **The skips were load-bearing.**

1. **Every backup was unrestorable and reported success.** The sealing key's
   only handle was discarded the instant it was created. You would have had
   a valid-looking artifact, a succeeded job, a matching digest, and nothing
   able to decrypt it. **Every backup taken before 0f480a1 is lost** — take
   a fresh one.
2. **Only two principals could do anything at all.** An internal authority
   read was gated on the caller already holding a capability named after the
   read itself — circular. Every narrowly-granted principal was inert, in a
   product whose purpose is delegating bounded authority.
3. **Applying a consumed plan minted a completed command id for work that
   never happened.** Nothing was applied twice, but a false completion
   record is worse than a duplicate: after the fact it is indistinguishable
   from a real one.
4. **A task could be admitted naming a verifier artifact that did not
   exist**, in the path that decides whether work counts as done.
5. **Every GitHub call and web read recorded unknown billing** instead of
   its real no-charge usage, corrupting spend records for non-model work.
6. **Creating a task returned HTTP 500** where it should have said which
   currency was wrong.

Three of these shared one cause worth naming: **a test double more
permissive than the thing it stands for.** The fake secret store accepted a
name where the real one demands a reference; the fake artifact store vouched
for artifacts that did not exist. Both produced defects that reported
success. That pattern is now recorded as practice, and a deliberate hunt for
more found the third instance rather than waiting for it to surface.

## Decisions I made for you

Quiet hours and your autonomy grant meant waiting would have cost the night,
so I ruled and recorded. Reverse any of them cheaply:

1. **Review eligibility**: the human whose own authority admitted a
   review-class request may decide that request; services, workers and
   agents never may. Without this nothing in the product could ever be
   approved.
2. **Authority gating**: the internal authority read is gated by its caller
   allowlist, not the subject's own capabilities. This is defect 2 above.
3. **OpenAI over OpenRouter**, on one documented difference: OpenRouter's
   Responses API is stateless and its only per-call record is keyed by an id
   you learn from the response body, so a dropped connection leaves nothing
   to reconcile against.

**A correction I owe you on that third one.** I said the conversation-first
pattern lets the adapter prove what happened after a timeout. It can confirm
a call *did* execute; it cannot prove one did *not*. An empty conversation
is equally consistent with "never ran" and "still running", so a step lost
before its response arrives is unknown forever, and its budget reservation
can never be settled. OpenAI is still right — OpenRouter cannot find the
call at all — but "reconcilable" was too strong a word from me. The design
also makes two physical calls per model step against a contract specifying
one; both are on the revision-3 list.

## Glossary for this report

- **Package root**: one directory the frozen plan treats as a unit of work; 36 in total.
- **Lane**: one independent work stream, run by one agent in its own copy of the repository.
- **Landing gate**: build, vet, formatting, linter, race detector, module-wide tests, and a mutation check, all run by me before a merge.
- **Mutation check**: deliberately break a safety rule and confirm a named test fails, then restore the code exactly.
- **Skip**: a test that declines to run, usually recording a known defect; a skip that outlives its cause hides the next defect.
- **Seam**: the boundary between two packages, where each one's own tests pass against a stand-in for the other.
- **Lease**: a machine-wide lock so only one heavy build or test runs at a time.
- **Revision 3**: the next version of the frozen specification, where the rulings above are ratified or reversed.
