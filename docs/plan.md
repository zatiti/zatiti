# Zatiti browser extension: chat with a governed Zatiti agent from any Chrome tab

Plan written 2026-09-28. Split layout: each epic lives in `docs/plans/`. 66 tasks, 3 done. Nothing below the ferro rename is implemented yet.

## 1. Context

Status: planning only. Nothing in v3 is implemented. This is plan v3 for the Zatiti Chrome extension, a complete plan rather than a diff. It applies the user decision to put WebSocket into the controller for Zatiti Cloud ("Let's build a Zatiti websocket server"). v2's separate gateway process is deleted: internal/browsergateway, the 0600 control socket, the capability bearer and the gateway_socket profile field are all gone. Nothing needed them once the browser command path runs in-process. See the changes list. Rebased on zatiti main 9cd94f7. Voice (revision 19) and streaming reply previews (revision 20: contract.ReplyStreams, server.Config.Streams, SSE POST /v1/replies/stream, streamsDone, Narrate pin, dependency lock revision 5) have landed. This plan's contract is revision 22, after the tool-gap epic E0T - this plan's first frontier epic, whose design was verified against main - at revision 21.

(0) Prerequisite: On main, no model tool call becomes a typed proposal (responses/interpret.go:176-185, tool_proposal_mapping_unspecified), and recorded reply proposals are not delivered as durable messages (launch-readiness.md:50). Epic E0T (the first frontier epic, contract revision 21) closes both before any browser journey can pass; the browser contract becomes revision 22.

What gets built:
(1) Ferro.
- v0.1.0 is done: the module rename to github.com/sirerun/ferro merged as PR #24 at 59178db, the annotated tag v0.1.0 points there, the module and the nested github.com/sirerun/ferro/deploy/cloud package resolve through proxy.golang.org, and the gitleaks scan is clean.
- v0.2.0 adds the chromedp-free public packages `page` and `bridge`, including execution identity fields and receipt states.
- sirerun/ferro is already public (gh api private=false; anonymous fetch returns 200), so no visibility gate is needed before the pin.

(2) Controller WebSocket transport in internal/server.
- One upgrade endpoint, GET /v1/ws, on three listeners:
  - the existing 0600 Unix socket, subprotocol zatiti.ws.v1, authenticated by the Authorization header on the upgrade;
  - the existing remote mTLS listener (Config.RemoteAddress), subprotocol zatiti.ws.v1, authenticated by the verified client certificate plus an optional matching bearer;
  - a NEW loopback-only browser listener (Config.BrowserAddress, literal 127.0.0.1 only). It accepts only zatiti.browser.v1 WebSocket upgrades with the exact Host 127.0.0.1:<port>, the exact pinned chrome-extension Origin, and first-frame server-proof-before-secret auth. Plain HTTP operations on it return 404.
- Call frames carry the byte-identical POST body. They run through one transport-neutral dispatch function extracted from handler.go:69-102, so decoding, MaxBodyBytes, authentication, principal resolution, application audit and the slog line are identical to POST /v1/operations/{id}.
- Unix and remote upgrades refuse any Origin header. This defeats cross-site WebSocket hijacking (CSWSH) through a browser-held mTLS certificate.
- It coexists with revision 20's SSE route POST /v1/replies/stream, which stays unchanged, human-only and the desktop's preview path. The browser listener never mounts it. The WebSocket route is registered in server.New on the mux streamMux returns, so it exists even when Config.Streams is nil.

(3) The internal/wshub hub, a new root. internal/server/stream.go and internal/contract/stream.go already exist (revision 20 ReplyStreams), and render.py:59-61 forbids overlapping roots. It provides:
- the session registry and per-principal data-free event hints (an event.list tail runs as the session's own principal);
- browser pairing and resume;
- the relay fence;
- listener binding (paired browser principals are refused on every other transport);
- one ferro bridge.Queue per label and a receipt ledger keyed by boot_id;
- the contract.BrowserChannel implementation;
- `internal/wshub/browserowner` (owner-side setup and pair orchestration) and `internal/wshub/wstest` (a Go test client and FakeExtension).
- browser reply-preview frames served from the controller's ReplyStreams instance (h.streams).

(4) A minimal internal/contract seam:
- a BrowserChannel interface (Exchange, Receipt);
- WSSession and WSHandler seam interfaces in internal/contract/ws.go, so server and wshub never import each other;
- an additive AdapterDependencies.Browser, placed after the revision-20 Streams field (adapter.go:68).

(5) The native adapter internal/adapters/browser.
- One Invoke is one in-process Exchange, which is one extension command.
- Authoritative refusals return failed. Uncertainty returns unknown with a ProviderReference.
- Reconcile parses Dispatch.ProviderKey and reads receipts only. When ProviderKey is empty, it queries by Dispatch.OperationID and settles only on positive journal records.
- Across a controller restart the new boot_id empties the ledger. Reconcile then consults only the extension journal, and every verdict that needed the old ledger stays unknown.

(6) cmd/zatiti wiring, in the S2 lane.
- serve reads <state>/browser/listener.json and <state>/adapters/browser.json once per runServeOnce, so first setup needs one serve restart. allow, remove, pair and unpair need none.
- srv.Close drains streams (close 1012) before ctl.Stop, so in-flight browser outcomes are recorded.
- The `zatiti browser setup|allow|remove|pair|unpair|status` commands.

(7) Governance, unchanged from v2:
- tools c7 (read), c8 (navigate) and c9 (act) are seeded;
- c8 and c9 are in the default review class with an exact-capability floor (a '*' rule never lifts review);
- worker-scope human_required rules;
- browser-worker isolation;
- desktop-only approval (decide.go:135);
- the desktop renders browser facts from digest-bound parameters.

(8) The MV3 extension in apps/extension. It connects to ws://127.0.0.1:<port>/v1/ws with zatiti.browser.v1, sends an application-level JSON ping every 20 s, keeps a write-ahead journal indexed by attempt and by operation_id, and has a compact hand-built token-styled panel.

(9) Shared design tokens: design/tokens/tokens.json plus the stdlib tools/designtokens generator with a -check mode.

The Flutter desktop is unaffected. It keeps HTTP over the Unix socket, and adopting the stream is optional later work (E13).

Data flow:

1. DF0 SETUP (owner): `zatiti browser setup --label work --worker W --allow https://site [--extension-id ID]`. W must be a dedicated browser worker; browserowner refuses a worker whose selected bindings include any external or local-effect tool other than its model tool. (1) One configuration draft stages: connection.create (provider browser, account_identity chrome:work, destinations = origins); binding.create for the connection and for c7, c8 and c9; worker-scope policy.create with human_required for c8 and c9; and worker.update appending the new binding ids while preserving the existing selection. Then configuration.plan and configuration.apply, with owner approval (interactive y or --yes). (2) grant.create or grant.update, direct and reviewed, for W: capabilities c7, c8 and c9, destinations = origins. (3) Write three 0600 files atomically in 0700 directories: - <state>/browser/listener.json {address 127.0.0.1:<chosen port>, extension_ids}; - <state>/adapters/browser.json (bounds only); - <state>/browser/labels/work.json {connection_id, worker_id, owner_principal_id, allowed_origins, principals: []}. (4) Print the ordered next steps: restart `zatiti serve` (listener.json and adapter profiles are read once per runServeOnce, cmd/zatiti/serve.go:132), run `zatiti browser pair`, then run `zatiti browser status --revalidate`, which calls connection.validate - revalidation runs only after pairing, because with no paired session the probe cannot be delivered and a not-sent observation must not mark the connection invalid. - SC0 Listener model. The Unix socket stays 0600 (socket.go:16). The remote listener keeps RequireAndVerifyClientCert (config.go:25-41 (the RequireAndVerifyClientCert check is at :38-40)). The browser listener binds only the literal 127.0.0.1 with a nonzero port, and Config.validate refuses 0.0.0.0, ::, localhost and any other host.
- SC1 Browser-listener admission happens before any upgrade. It requires the exact Host 127.0.0.1:<port>, the exact Origin chrome-extension://<pinned id>, and the zatiti.browser.v1 subprotocol; anything else gets 403. The browser mux registers only GET /v1/ws; POST /v1/operations/* and POST /v1/replies/stream both return 404, and plain GETs are refused. How this defeats CSWSH and DNS rebinding: - Browsers always send Origin on WebSocket handshakes, and page script cannot set it, so web pages and other extensions fail the exact match. - A rebound domain sends Host evil:<port> and Origin http://evil, and both fail. - Non-browser local processes can forge Origin and Host, which is why SC2 exists.
- SC2 Server-proof-before-secret. The pairing code never crosses the wire (the client sends code_mac and the hub answers server_mac). The extension refuses command origins outside the authenticated welcome and policy allowlist.
- SC3 Pre-auth limits: - the hello deadline is 5 s (4408); - codes are 128-bit, single use and expire after 120 s; - after 5 consecutive pairing failures on an offer, that offer is burned; - a limit of 10 handshake failures per minute closes with 4429, in per-id and per-flow buckets (pair vs resume) with slots reserved per label; - at most 8 pending offers (one per label).- the browser listener runs under a LimitListener semaphore with ReadHeaderTimeout 2 s, MaxHeaderBytes 8 KiB, keep-alives off and SetReadLimit(4096) before authentication; - paired and offer verification material is cached in memory at startup and on pair, so unauthenticated frames never trigger Keychain reads (each /usr/bin/security exec is otherwise pre-auth process spawning); - supersede (4409) happens only after the new session proves possession; - residual: loopback TCP is reachable by every local OS user, not only the owning user; the 0600 files and the identity-layer binding bound what a squatter or reader can do.
- SC4 Credentials: - The extension never holds a controller credential. Pairing mints a separate link secret; the extension stores only the link secret (IndexedDB) and the welcome carries it once. - The controller credential for the browser principal lives in the SecretStore under browser/<label>/credential (raw credential in the store by design), marked transport=browser_listener, and is read once by the hub at Bind into memory. - Hub-side paired records hold only the link digest and K_s. - Pending offers are 0600 files under <state>/browser/offers/<id> (O_EXCL, consumed by rename), not SecretStore keys, so headless multi-process backends stay consistent; only serve processes write SecretStore browser keys. - credential.provision runs only when the offer is consumed; pair blocks until consumption or TTL and then revokes the unused principal. Unpair deletes the key. - Stream sessions keep a private in-memory credential copy and pass a fresh copy to each authentication (identity zeroes its input). The copy is zeroed on close.
- SC5 Per-call and per-frame re-authentication: every call frame on every listener, and every browser frame including the 20 s ping, re-authenticates. Revocation therefore takes effect within 20 s (close 4401), and relayed calls fail immediately.
- SC6 Listener binding. Identity marks browser credentials transport=browser_listener, and the Unix, remote and HTTP handlers refuse such rows fail closed regardless of label files. operationHandler.authenticate (handler.go:110-143), which both handle (:97) and the SSE route (stream.go:37 and :48) call, additionally asks WS.BoundTransport(principal), so a bound principal is refused on the reply stream too. Label files are MAC'd with a SecretStore-held key; a missing, malformed or MAC-failing label refuses every browser principal rather than unbinding it.
- SC7 Origin refusal on the Unix and remote streams: any Origin header is refused with 403. This defeats CSWSH through a browser that holds the user's mTLS client certificate. installation.init is refused on every stream.
- SC8 Audit parity: stream calls use the same dispatch, MaxBodyBytes, authentication, principal resolution, application command records and events, and slog fields (transport local-ws, remote-ws or browser-ws) as POST. Hub-internal calls (tails, fence lookups) log at Debug with origin=hub.
- SC9 Relay fence (browser): - the allowlist is exactly conversation.create, conversation.list, conversation.get, conversation.message.send, conversation.message.list, command.get, review.get and operation.get; every other operation id (including review.list, operation.list, review.decide, installation.init, event.list and event.get) is refused before dispatch; - the browser principal's grant is exactly the allowlist plus event.list, with no '*' narrow rules; - conversation create, send and list are fenced to {self, owner, worker}; - review.get and operation.get are filtered to c7-c9 on this label's connection; - mutations require a submission_key; - a 'command' frame sent by a client is a protocol error (1008).
- SC10 Per-connection limits: - read limit MaxBodyBytes + 64 KiB, with the input checked against MaxBodyBytes exactly as HTTP does, and 4096 bytes on browser frames before authentication (raised only after); - at most 8 in-flight calls (excess gets error busy and is not dispatched); - outbound queue of 64 frames, with hints coalesced into resync; - 10 s write timeout, 60 s idle timeout (4408); - at most 4 streams per principal on the Unix and remote listeners; - one browser session per label, where a newer one supersedes the older (4409); - listener caps of 64 on Unix and remote and 8 on the browser listener. replies frames coalesce to the latest snapshot per conversation (like hints) and are never queued behind result frames. Above 32 queued frames the hub drops the pending preview snapshot and waits for the next notify, because previews are complete snapshots.
- SC11 Event minimization: hints carry no data. The only data-bearing push is replies (CC19): the session's own requester-scoped previews, re-authorized per frame, in fenced conversations only. Tails run as the session principal, so controller scope-visibility applies. Browser message hints are fenced on conversation_id, and review and operation hints are pushed only after authorization. Browser sessions are default-deny on event kinds: an explicit allowlist is forwarded and everything else is dropped in the hub before serialization. Subscribe requires a scope, and browser principals are pinned to a worker-, conversation- or principal-narrow scope, never installation scope; review and operation hints and relayed review.get and operation.get reads are fenced by owning principal or paired worker.
- SC12 No out-of-process command path: the only path to an extension command is contract.BrowserChannel, injected into AdapterDependencies and reached only through governed dispatch. This replaces v2's control socket and capability bearer.
- SC13 Every page action is a governed effect. Destinations are checked in five places: execution, _connections.resolve, the adapter, the hub (which re-reads the label file per exchange) and the extension.
- SC14 The review floor fails closed for c8 and c9: they are in the default review class, only an exact-capability rule lifts review, and setup adds human_required rules. Approval is bound to the digest and happens only in the desktop (decide.go:135).
- SC15 Browser-worker isolation: a browser worker holds only c7, c8, c9 and its model tool, so hostile page text cannot drive other external tools. 'restricted' is a label only (responses/contextdoc.go:122-136).
- SC16 Sensitive-field refusal for fill, select, key and extract covers password, one-time-code, current-password, new-password and cc-* fields. Both the adapter and the extension enforce it. Snapshots never include input values.
- SC17 Trusted-input verification: a CDP hit-test in an isolated world runs before mousePressed, and focus is verified before dispatchKeyEvent. key accepts named keys only.
- SC18 Link and form containment: the absolute href and the form action and method are part of the target identity, and cross-origin targets are refused.
- SC19 Honest outcomes and no resend: failed versus unknown, and a Reconcile that only reads. A negative conclusion requires a sealed receipt: receipt_query atomically seals a refused/expired tombstone (keyed by attempt_id and operation_id) for any attempt unseen or received-not-started past its deadline, and failed is concluded only from that sealed answer, never from absence. The extension journals received before the deadline check and serializes journal transitions behind a single writer; received->started is a compare-and-set against the seal. Empty-ProviderKey reconciliation settles only on positive records.
- SC20 Write-ahead journal: received and started entries are awaited before any input. Nothing is retried after input starts. The debugger always detaches. Submission keys are persisted before a send.
- SC21 Keepalive: a JSON ping every 20 s (the JS API cannot see protocol pings, and MV3 idles after 30 s) plus a chrome.alarms reconnect. Chrome 116 or later is required.
- SC22 Supply chain: modules are pinned in go.sum and the lock, with library-family importer scopes. Vendored JS is byte-verified against ferro v0.2.0. The zatiti binary links no chromedp, cdproto or aws-sdk.
- SC23 Validation freshness (24 h) is enforced by _connections.resolve and renewed only by the owner.

## 7. Operating Procedure

- A task is done only when its acceptance and `acc:` check pass, its paired tests are green, the PR is merged to main with CI green, and results are reported as observed.
- Follow AGENTS.md: write only inside your assigned root; never hand-edit generated AGENTS.md or shared contracts; spec changes run `python3 tools/specgen/render.py` then `--check`; go.mod, go.sum and dependencies.lock.json belong to the integration owner.
- Before a multi-package `go build`/`go test`/`golangci-lint` or `flutter` build on the Mac mini, check `uptime` (hold above 10) and claim `R-build-lease`; release immediately after. At most one `-race` lane at a time.
- Run `gofmt`, `go vet` and `golangci-lint` on touched packages; `dart format` and `flutter analyze` for apps/desktop; `node --test` for apps/extension. Small logical commits; never commit files from different roots together.
- Never commit the untracked files that another session keeps in the checkout root.
- There is no production environment yet (pre-release); live verification means the local Mac dogfood task.

Why: the user decided WebSocket belongs in the controller for Zatiti Cloud. In-process placement also removes the duplicated auth and audit surface and the out-of-process command path.
